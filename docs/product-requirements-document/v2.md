# PRD: Soundcheck v2 — Deeper editing

Terms in **bold** are defined in [`CONTEXT.md`](../../CONTEXT.md). This replaces the roadmap-level v2 doc now that the [MVP](mvp.md) has shipped.

## Problem

The MVP can sketch a song but not finish one. Notes can only be placed on a drum-style grid, nothing in the mix can move over time, every Track goes straight to the **Master**, the tempo is fixed for the whole song, and the only sounds are the built-in ones with their factory settings.

## Goal

Turn the MVP from "sketch a song" into "finish a song": precise note editing, mix movement over time, richer routing, the musician's own sounds and settings, and a way for others to add **Instruments** and **Effects**. Every new feature is plain **Project** data, so v3's **Assistant** can reach it.

## Who it's for

The author first, as in the MVP, and then the first outside developers writing **WASM Plugins**.

## Architecture constraints

- Everything in the MVP's constraints still holds: the **Audio Engine** does all sound ([ADR 0001](../architectural-decision-record/0001-audio-engine-in-rust.md)), the UI never processes audio, desktop first ([ADR 0002](../architectural-decision-record/0002-mvp-is-a-desktop-app.md)).
- Every new feature is **Project** data, reached through the same commands as the UI, undo history and **Assistant**. Every **Project** format change bumps the schema version and ships a migration, so an MVP **Project** opens in v2 unchanged in sound.
- Positions stay in ticks. The tempo map is the one place ticks become seconds; playback, export and **Audio Analysis** all use it.
- The mixer's signal flow becomes a graph (Tracks → **Buses** → **Master**). It is always acyclic: commands refuse a cycle, and validation rejects one on load, so the engine never sees one.

## User stories

### Editing

1. As a musician, I can open any **Pattern Clip** in the **Piano Roll** and draw, delete, move and resize notes at any pitch and length.
2. As a musician, I can select several notes, copy and paste them, change their velocity in a velocity lane, snap to a grid (off, 1/4 to 1/32, triplets), and quantise them.
3. As a musician, I can open a drum **Pattern Clip** in the **Piano Roll** and see its rows named by **Pad**.

### Time

4. As a musician, I can add a **Tempo Change** anywhere in the song, and a time-signature change at any bar line.
5. As a musician, when the tempo changes, **Pattern Clips** follow it and **Audio Clips** start where they did and play at their natural speed.

### Mixing

6. As a musician, I can add a **Bus**, route Tracks or other **Buses** to it, and give it an **Insert Chain**, volume, pan, mute, solo and a meter.
7. As a musician, I can add a post-fader **Send** from any Track or **Bus** to a **Bus**, e.g. one Reverb fed by many Tracks.
8. As a musician, I can add the Delay **Effect** to any **Insert Chain**.
9. As a musician, I can draw **Automation** for any numeric Track, **Send**, **Bus**, **Master**, **Instrument** or **Effect** setting in an **Automation Lane**, and hear it in playback and export.

### My sounds

10. As a musician, I can save an **Instrument's** or **Effect's** settings as a User **Preset** and load it into any **Project**.
11. As a musician, I can save a Drum Sampler's **Pads** as a **Kit**, samples included, and load it into any **Project**.
12. As a musician, I can add sample folders to a sample browser, audition a file, and drop it onto an **Audio Track** or a **Pad**.

### Plugins

13. As a developer, I can write an **Effect** or **Instrument** against the Soundcheck SDK, declaring its settings up front, and have the app draw controls for them.
14. As a musician, I can install a **WASM Plugin** and use it like a built-in **Instrument** or **Effect**, including in **Automation** and **Presets**.
15. As a musician, a **Project** that uses a **Plugin** I don't have still opens, and sounds right again once I install it.

## Requirements

### Piano Roll

- Edits the same **Pattern Clip** notes as the **Step Sequencer**; either editor shows the other's changes.
- Each edit is one undo step.

### Tempo Changes

- The **Project** holds a tempo map: the starting tempo and time signature, plus a list of **Tempo Changes**. Changes are instant; there are no tempo ramps in v2.
- An **Audio Clip's** start stays on its tick; its length is derived from its audio in seconds, so its end tick moves when the tempo under it changes. Audio is not time-stretched.
- The ruler, grid, metronome, loop region, export and **Audio Analysis** ranges all follow the tempo map. The **Assistant's** context describes it, and `set_tempo` says when the song has **Tempo Changes**.

### Routing

- Each Track and **Bus** has one output: the **Master** or a **Bus**.
- **Sends** are post-fader, with a level. A pre-fader option is later.
- A change that would create a cycle is refused with a message saying why.

### Delay

- Time as a tempo-synced note value (1/16 to 1/1, with dotted and triplet) or in milliseconds; Feedback; a high-cut on the repeats; Ping-pong on or off; Mix.
- Factory **Presets**: "Slapback", "Quarter echo", "Dotted-eighth ping-pong".

### Automation

- Breakpoints with linear ramps between them, and a per-breakpoint hold (a step).
- Drawn only. Recording **Automation** by moving a control is later.
- Automatable: every numeric Track, **Send**, **Bus**, **Master**, **Instrument** and **Effect** setting. Mute, solo and **Effect** bypass are not automatable in v2.
- An automated setting follows its **Automation** in playback and export. The **Assistant** is told a setting is automated, and a tool that sets it says that **Automation** overrides it.

### Presets, Kits and samples

- User **Presets** and saved **Kits** live in an app-level library outside any **Project**, behind a platform interface: the app-data folder **[desktop]**, IndexedDB on the browser dev host.
- A **Kit's** samples are copied into the library when it is saved, and into the **Project** when it is loaded, so a **Project** still owns all its audio.
- Sample browser **[desktop]** **[web]**: folders the musician adds, remembered app-wide; audition goes straight to the audio output at a fixed preview level, bypassing the mixer; a dropped file is copied into the **Project**. In the browser dev host a folder is chosen with the File System Access API's directory picker and its handle kept in IndexedDB (Chromium), so it is remembered too, though the browser may ask permission again before reading it; elsewhere a folder input lends its files for the session only.

### Plugin SDK

- How the **Audio Engine** hosts **WASM Plugins** (runtime and interface) is decided by a spike and recorded as an ADR before any hosting is built. The leaning is a small C-style ABI, runnable in both an embedded runtime **[desktop]** and the host's WebAssembly (browser dev host).
- A **Plugin** declares its settings (name, range, unit, default) up front; the app draws its controls from them, and they are **Project** data like a built-in's.
- **Plugins** are installed into an app-level Plugins folder behind the same platform interface as the library.
- A **Project** stores a **Plugin's** id, version and settings. When a **Plugin** is missing, the **Project** still opens, the slot shows "missing Plugin", an **Effect** passes audio through, an **Instrument** is silent, the settings are kept exactly, and the **Assistant** is told it is missing.
- The SDK is marked unstable until example **Plugins** in `examples/plugins/`, built only against the SDK and its docs (checked in CI), prove it.

### The Assistant

- No new tools in v2; that is v3. Every v2 issue keeps the **Assistant** correct: its context describes the new data, and existing tools behave correctly around it.

## Acceptance criteria

- [ ] An MVP **Project** opens in v2 and renders identically.
- [ ] A song with a **Tempo Change**, a **Bus** fed by two **Sends**, a Delay and volume **Automation** plays and exports with each audible where expected (render tests).
- [ ] A cycle in routing cannot be created by hand, by command or by loading a file.
- [ ] A User **Preset** and a saved **Kit** made in one **Project** load into another.
- [ ] An example **WASM Plugin** **Effect** and **Instrument** built from `examples/plugins/` run on desktop and the browser dev host.
- [ ] A **Project** using a missing **Plugin** opens, and sounds right after the **Plugin** is installed.
- [ ] Every v2 feature can be undone and redone, and the **Assistant's** existing tools still pass their tests.

## Out of scope for v2

- New **Assistant** tools, conversations, other models (v3)
- Tempo ramps, recorded **Automation**, pre-fader **Sends**
- Time-stretching or pitch-shifting audio
- VST3/AU, installers, collaboration (v4)

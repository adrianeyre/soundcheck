# v4: Desktop and ecosystem

Terms in **bold** are defined in [`CONTEXT.md`](../../CONTEXT.md). This is a roadmap-level doc; it becomes a full PRD once [v3](v3.md) ships.

## Goal

Soundcheck works with the gear and plugins musicians already own, installs like any other app on Windows, macOS and Linux, and can be used by more than one person on the same **Project**.

## Scope

- **The other platform**: the MVP ships on the desktop ([ADR 0002](../architectural-decision-record/0002-mvp-is-a-desktop-app.md)), so consider a browser build. The **Audio Engine** core is shared either way ([ADR 0001](../architectural-decision-record/0001-audio-engine-in-rust.md)). Decided in [ADR 0006](../architectural-decision-record/0006-a-browser-version-beside-the-desktop-app.md): ship both, with the **Browser Version** as the lighter one.
- **Low-latency recording** (desktop): direct audio-driver access — ASIO/WASAPI on Windows, CoreAudio on macOS, JACK/PipeWire on Linux — including multi-input interfaces and hearing yourself through **Effects** while recording.
- **VST3 hosting** (desktop): scan, load and run purchased third-party plugins, show their own windows, and save their state in the **Project**. AU on macOS as a possible addition. Proposed in [ADR 0008](../architectural-decision-record/0008-vst3-plugins-run-in-a-helper-process.md): each **VST3 Plugin** runs in a helper process of its own, which the **Desktop App** drives through shared memory, and its window is the helper's, kept above Soundcheck's.
- **Installers, signing and auto-update** for Windows, macOS and Linux. Proposed for Windows in [ADR 0009](../architectural-decision-record/0009-an-nsis-installer-signed-with-whichever-secret-is-set.md): an NSIS installer, per user, signed through Azure Artifact Signing or a PFX certificate, whichever secret CI has, and built unsigned until one is. Proposed for macOS in [ADR 0010](../architectural-decision-record/0010-the-mac-app-is-signed-ad-hoc-or-with-a-developer-id-and-notarised.md): an app and a disk image for Apple silicon, signed ad hoc until CI has the `APPLE_*` secrets, then with a Developer ID and notarised. Proposed for auto-update in [ADR 0011](../architectural-decision-record/0011-the-desktop-app-updates-itself-from-the-latest-github-release.md): Tauri's updater, which installs only what the updater's own key signed for that version, fed from the latest GitHub Release; a `v*` tag makes the Release, and nothing updates itself until the maintainer makes the key.
- **Collaboration**: several people editing one **Project**, live or by syncing changes. Proposed in [ADR 0007](../architectural-decision-record/0007-collaboration-by-an-ordered-log-of-changes.md): every copy applies one ordered log of Changes, offline through the **Shared Project**'s folder and live through a **Relay**, and undo is a new Change that never overwrites a **Collaborator**.

## Dependencies

- v3 complete.
- A Mac (or macOS CI runner) and an Apple Developer account for macOS builds and notarisation ([ADR 0010](../architectural-decision-record/0010-the-mac-app-is-signed-ad-hoc-or-with-a-developer-id-and-notarised.md)); a code-signing certificate for Windows (Azure Artifact Signing, [ADR 0009](../architectural-decision-record/0009-an-nsis-installer-signed-with-whichever-secret-is-set.md)).
- Steinberg's VST3 SDK (C++, MIT-licensed). The C++ is a helper program the Rust drives over a pipe and shared memory, not a library it links ([ADR 0008](../architectural-decision-record/0008-vst3-plugins-run-in-a-helper-process.md)). Steinberg's terms for the VST trademark and logo apply wherever Soundcheck names VST.

## Risks

- **VST3 hosting is the riskiest item on the whole roadmap**: third-party plugins crash, each has its own licensing and copy protection, and embedding their native windows next to a webview UI is fiddly. Plugins should run in a separate process so one crash doesn't take down the song. [ADR 0008](../architectural-decision-record/0008-vst3-plugins-run-in-a-helper-process.md)'s spike shows a crash costing only its own Plugin, in the block it happened in; windows and purchased, copy-protected plugins are still to be checked by hand on Windows.
- **The Assistant can't see inside third-party plugins**: a VST's internal settings aren't **Project** data in the way built-in **Instruments** and **Effects** are, so the **Assistant** can only reach whatever settings the plugin exposes.
- **Collaboration conflicts with one-step undo**: undoing your own **Request** while someone else is editing needs a sync model designed for it. [ADR 0007](../architectural-decision-record/0007-collaboration-by-an-ordered-log-of-changes.md) is that model; its spike shows undo reaching only your own Request while others edit.
- **Cost of distribution**: signing certificates and developer accounts are a recurring cost, and per-OS testing multiplies QA effort.
